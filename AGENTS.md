# Sharhoroots project guidance

This repository is an Obsidian vault published with Quartz 4. It serves genealogy, history, and lore researchers of the former Sharhorod raion and surrounding area.

## Working with the vault

- Preserve existing Markdown structure, YAML frontmatter, Obsidian wikilinks, embeds, and naming conventions. Prefer the conventions of nearby notes over introducing a new format.
- Write new or revised article prose in Ukrainian unless the user requests another language. Preserve original-language quotations and source titles where useful.
- Do not invent historical or genealogical facts, identities, dates, or source details. Distinguish what a source states from interpretation, evidence-based hypotheses, and oral tradition. When direct proof is unavailable, include the strongest useful inference supported by inspected evidence in the relevant article, even if it is provisional: mark it explicitly with calibrated language such as *можливо* or *ймовірно*, explain the evidence and reasoning, and state what remains unproven. Cite the evidence; never make an inference sound like a source's assertion. Uncertainty wording is not a substitute for evidence: if the available material supports no reasonable inference, say that the question remains open rather than speculate.
- Preserve citations and source links when editing claims. If a claim cannot be verified directly, recast it as an evidence-based inference when warranted, or flag what remains unknown; do not silently strengthen or change it. A search snippet, OCR result, or another page citing a source is not the same as inspecting that source.
- Keep reader-facing evidence qualifications separate from research-process notes: article prose should explain what the cited evidence does and does not establish, while failed access attempts, HTTP/tool errors, and agent-environment limitations belong in the relevant `tasks/` research log, not the article. If research yields no new established fact but does support a useful inference, add that qualified inference to the target article. Leave the article unchanged only when there is no new supported fact or useful evidence-based inference to communicate.
- Keep place names, historical administrative units, and transliterations consistent with the source and surrounding notes; do not normalize them by guesswork.
- For requests to find and source historical facts, load the `research-facts` skill. For requests to reorganize, move, or rename vault articles, load the `curate-articles` skill.
- For historical or genealogical research, follow `research-facts`: check existing tasks and reusable records in `sources/` and local copies in `books/` before searching; search the web, inspect and record at least one source document, and save each worthwhile unanswered follow-up as its own atomic note in `tasks/`. A source record is a retrieval aid, not evidence: inspect the cited document and record its exact locator. Keep large or temporary downloads and command output in ignored `.agent-work/`; only intentionally retained source copies belong in ignored `books/`. Check existing tasks first; a task may target more than one article, but must have one research question and one deliverable. For an existing research task, record supported facts and evidence-based inferences in the task (`found`), then apply them—with uncertainty and evidential limits explicit—to their target articles (`done`). Use `fail` only when no new supported fact or useful inference can be added and no requested source is still pending from the user. Add relevant Obsidian wikilinks and bold an article's title at its natural first mention when revising its prose. When a research request concerns an existing article, update that article with supported findings and useful qualified inferences; a standalone research request with no relevant article target still does not authorize creating or revising an article unless asked.
- Use ignored `.agent-work/` as a disposable playground for exploratory work, including `curl` downloads, temporary scripts, extracted text, and command output; create subdirectories as useful. Do not put credentials, canonical notes, or reusable source copies there.
- When an article's published path changes, update `content/_redirects` and affected internal links in the same change. Preserve existing redirect entries and verify the old and new published paths; do not assume every route has the same prefix.
- Quartz builds the `content/` directory by default and ignores paths matching `private`, `templates`, `.obsidian`, and `**/*.excalidraw.md`. Keep research tasks in the repository-root `tasks/` directory, outside the published content tree; never copy them into generated site output.
- Do not edit generated output or local Obsidian workspace state as a substitute for editing its source.

## Quartz and verification

- `npm run docs` runs the repository's Quartz build with its local preview server.
- `npm run check` runs TypeScript checking and Prettier validation.
- `npm test` runs the TypeScript tests.
- Run `npm run check` after TypeScript or formatting changes; run `npm test` when changes affect tested behavior. For content-only edits, preserve note conventions and links and report any checks that were not run.
- Do not reformat unrelated files or run `npm run format` across the repository unless explicitly requested.
