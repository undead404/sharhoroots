# Nysh discovery and archival reading

Read before Nysh work or opening archival scans. For a new settlement, fond, or explicitly requested surname investigation, read the discovery rules after checking local tasks, source records, and books. Code paths and commands below are relative to the repository root.

## Nysh CLI for archival research

- Archival discovery & person-index research: use services in [.agents/skills/research-facts/references/search-services.md](search-services.md): Duck Inspector, ЦДІАК-442, UaRoots, Archival.name, JewishGen, and FamilySearch. Use specialist registry in [.agents/skills/research-facts/references/specialist-databases.md](specialist-databases.md) by triggers and priorities. Do not search every database or repeat searches of the same collection without cause. Reuse authenticated browser sessions and request human searches when gated. Duck Inspector returns <=50 results; record fuzziness and narrow capped searches. Use historical place names and period jurisdictions on failure. These routes supplement research and do not authorize unsolicited surname searches, account creation, payments, or archival scan reading by LLM.
- Local setup in `NYSH.md`. From this repository, run `sh scripts/nysh.sh <command>` to select the separate workspace; do not initialize a Nysh workspace inside the vault.
- Consult `shepit.poshuk` as a discovery step after checking tasks, `sources/`, and `books/` when beginning research on a settlement or fond, or an explicitly requested surname. Read `nysh share dovidka` and permissions via `sh scripts/nysh.sh share vyklyky --json`. Request dossiers: `sh scripts/nysh.sh share vyklyk shepit.poshuk --param misce="Шаргород" --param oblast="Вінницька" --json` or topical `--param q="..."`. Resolve candidates with the user if `stan: choose`. Record queries, locators, and limits; hints and summaries are leads, not evidence. Inspect underlying documents before applying findings.
- Specialist Nysh workflows remain specialist tools. Check tasks, `sources/`, and `books/`, then load the matching specialist skill. Load `find-surname` only on explicit request.
- **Archival reading depends on the script:**
  - **Cyrillic or Latin handwriting:** Never pass scan images, page screenshots, crops, or visual scan data to an LLM, and do not use LLM vision to read or verify them. This applies to visual arbitration of OCR/HTR: use local OCR/HTR text and human review instead.
  - **Other scripts (Hebrew, Yiddish, Ottoman Arabic):** LLM vision is permitted for reading and verification when reliably expected from catalog metadata, existing text, or tools (subject matter alone is not enough). Record the routing basis and limit visual reading to non-Cyrillic/non-Latin passages; crop mixed-script pages.
  - Visual evaluation of candidate article photos under `find-illustration` remains allowed. Local OCR and specialist HTR (`nysh read`) remain allowed; prefer suitable local HTR for handwriting.
- When asking the user to read Cyrillic or Latin archival text, provide automated OCR/HTR alongside the request whenever possible. Reuse existing output or run a bounded attempt under the relevant Nysh skill. For handwriting, prefer Nysh HTR over generic OCR. Include raw machine transcription labelled as unverified OCR/HTR, identifying engine/model, and preserving errors/competing readings. Ask the user to confirm/correct the needed passage. Do not ask users to transcribe other scripts; use OCR/HTR or the vision exception above.
- If local OCR/HTR is unavailable, fails, or leaves Cyrillic/Latin text unresolved after a bounded attempt, stop automated attempts and ask the user. Identify scans by case/path, filename, PDF page (and printed page if known), and name the specific field/passage. Ask only for data needed to answer the task, not a full-page transcription. Once the user supplies or confirms a reading, treat it as established.
- Treat Nysh results as leads with explicit coverage limits, not historical evidence. Inspect underlying sources and cite exact locators.
- After Nysh work produces shareable results, send them to Супряга as part of task completion (standing authorization granted). Load `share-case` (and `case-notebook` for eligible notes/readings). Check pool contents, validate contributions with dry-run, publish text, geometry, case metadata, and eligible notes, then verify receipt. Never upload scan images, private research notes, family hypotheses, credentials, or restricted material.
- Use stateful/costly workflows (case download, HTR, record ingest, cloud) only when fitting the request; obtain confirmation before paid/remote work or publishing outside standing Супряга authorization.
- Do not run `nysh site build` for this repository; Quartz builds the site.
